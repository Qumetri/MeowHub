# Russia circumvention, October 2026: what works, and what to add to a self-hosted stack

> Research report, dated 2026-10-08. Kept permanently; the "What we did with it" section at the end records decisions. **[LC]** = low confidence (single/anecdotal report).

## 1. What works now

| Path | Mobile, normal mode | Home ISP | Whitelist mode |
|---|---|---|---|
| Reality TCP+Vision | Works, but most exposed. It can't mux, so it trips the ">3 parallel handshakes per SNI" freeze ([habr](https://habr.com/ru/articles/1047442/)) | Port-443-specific connection policing on MTS/MGTS, Rostelecom and others; another port fixes it ([n4p#546](https://github.com/net4people/bbs/issues/546)) | Dead (L3 drop) |
| Reality/TLS + XHTTP, xmux | Best TCP option. On MegaFon, packet-up and stream-up run at ~2 Mbit while **stream-one is fast** [LC] ([ntc](https://ntc.party/t/25362/32)) | Works | Only via an RU CDN (see §4) |
| gRPC | Works. Fully multiplexed by default, so RPRX suggests it as the alternative to tuning xmux ([#6376](https://github.com/XTLS/Xray-core/issues/6376)) | Works | No |
| Hysteria2/QUIC | Mixed. T2: QUIC fully blocked; MegaFon: intermittent ([ntc](https://ntc.party/t/20340)); otherwise "most resilient for now" ([habr](https://habr.com/ru/articles/1047442/)) | Mostly works | No |
| AmneziaWG | 2.0 is being phased out by Amnezia. AWG to WARP breaks every 10–30 min on MegaFon (Sept) ([ntc](https://ntc.party/t/16325/1315)) | Works | No |
| SS-2022 | Works but flagged as "unknown encrypted" and was briefly blocked ([n4p#546](https://github.com/net4people/bbs/issues/546)) | Works | No |
| MTProto FakeTLS | Hosting IPs failed in June; **a home server was unaffected** ([ntc](https://ntc.party/t/22506/117)) | Works | No |
| VLESS Encryption, Finalmask (Sudoku/noise), TUIC | Too new for field data. In stable Xray since 25.9.5 and 26.3.27 ([rel](https://github.com/XTLS/Xray-core/releases/tag/v26.3.27)) | ? | No |

**SNI.** TSPU now ties well-known SNIs to their real IPs ("grey lists"; a GitHub SNI died until changed) ([ntc](https://ntc.party/t/23653/62)); google.com/github.com SNIs drop after ClientHello, random/empty SNIs get throttled ([ntc](https://ntc.party/t/16061/1250)). **Our `www.icloud.com`, `dl.google.com`, `ya.ru` and Apple SNIs on a residential IP fit the "burned" pattern exactly.** Most likely cause of "443 dead", plus n4p#546. Community consensus: when you own a domain, **use self-steal or real TLS + XHTTP behind the web server** ([ntc](https://ntc.party/t/26336/4)).

**Bans are scan-driven.** 4 Aug and 21 Sep waves banned entry IPs in popular VPS ranges ([n4p#671](https://github.com/net4people/bbs/issues/671), [ntc](https://ntc.party/t/25528/35)). An exposed 3x-ui subscription port visible on Censys got one server blocked ([ntc](https://ntc.party/t/25993)). RU apps compare the exit IP with the entry IP and report VPNs ([ntc](https://ntc.party/t/26076/20), [Mintsifry methodology](https://ntc.party/t/23842)).

## 2. The ~16–20 KB freeze

- **Hosting-ASN-specific.** A TLS 1.3 connection to a foreign datacenter AS freezes after about 15–20 KB from server to client, with no RST ([n4p#490](https://github.com/net4people/bbs/issues/490)). It applies to large hosters except for "white" SNIs from the same AS ([ntc](https://ntc.party/t/22516/177)).
- **Residential:** no report found of it hitting residential ISP space, so a home IP is very likely exempt [LC: unverified for our IP]. Check from a Russian line with [dpi-ch / RU::TCP 16-20](https://github.com/hyperion-cs/dpi-checkers).
- **What the cited Xray threads are actually about** is a different rule: more than 3 parallel TLS handshakes to one SNI within ~350–400 ms causes a ~120 s freeze. It applies only together with a suspicious subnet and a Chrome/Safari fingerprint ([habr/hyperion](https://habr.com/ru/articles/1044396/), [zapret notes](https://publish.obsidian.md/zapret/VLESS/dpi-tls-june-2026)). Xray changed the xmux default from maxConcurrency 1 to maxConnections 6 (27 Jun) and then to **3** (28 Jul, "anti-TSPU"). A Moscow report says 3 has held for more than a month, while more than 3 gets cut on MTS mobile ([#6376](https://github.com/XTLS/Xray-core/issues/6376), [18e2839](https://github.com/XTLS/Xray-core/commit/18e283909ca253d4220136eccca0a27006ea709f)). sing-box-lx copied this in v1.14.2-lx.6 ([issue #32](https://github.com/Leadaxe/sing-box-lx/issues/32)). [#6527](https://github.com/XTLS/Xray-core/discussions/6527) (maxConcurrency 5) doesn't bound connections; [#6040](https://github.com/XTLS/Xray-core/discussions/6040) is CDN billing, irrelevant; [#4113](https://github.com/XTLS/Xray-core/discussions/4113) is the modes reference.

**Recommended client `extra`.** List every xmux field: a partially filled xmux block disables all the defaults ([sing-box-lx #32](https://github.com/Leadaxe/sing-box-lx/issues/32)). Subscriptions don't carry xmux ([3x-ui#5194](https://github.com/MHSanaei/3x-ui/issues/5194)), so clients on Xray older than 26.7.28 need this pasted by hand.

```json
"xmux": {"maxConcurrency": 0, "maxConnections": 3, "cMaxReuseTimes": 0,
         "hMaxRequestTimes": "600-900", "hMaxReusableSecs": "1800-3000"},
"xPaddingBytes": "100-1000", "scMaxEachPostBytes": "500000-1000000", "scMinPostsIntervalMs": "10-50"
```

([ntc](https://ntc.party/t/24845/47)) Use fingerprint `firefox` or `edge`, not `chrome`, and avoid `randomized` ([habr](https://habr.com/ru/articles/1047442/)). For iOS drops, use maxConnections 1–2 [LC] ([ntc](https://ntc.party/t/13855/475)).

## 3. Xray #6797 verdict

- **Client-only.** The bug is in the XHTTP *dialer*: x/net's `http2.Transport` wraps `net/http` on Go 1.27, so every waiting request opens its own TCP connection while handshakes hang ([#6797](https://github.com/XTLS/Xray-core/issues/6797)). **Our server on 26.9.9 is not affected.** It does matter for clients built on Xray 26.9.8 or later (pre-releases): that burst of connections is exactly what triggers the TSPU connection-count freeze.
- **Not fixed in 26.9.30.** It still uses Go 1.27 with x/net 0.59.0, has no `http2legacy` tag in the release workflow ([compare](https://github.com/XTLS/Xray-core/compare/v26.9.9...v26.9.30)), and the issue is open.
- **3x-ui [v3.9.0](https://github.com/MHSanaei/3x-ui/releases/tag/v3.9.0)** (3 Oct) bundles 26.9.30 and adds a native TUIC v5 server. **Breaking:** the XDNS finalmask wire format changed, so clients of our mKCP+XDNS inbound need Xray 26.9.30 or later.

## 6. Recommended additions for this server

1. **VLESS + XHTTP + real TLS behind Caddy on :443 (primary).** Xray inbound on `127.0.0.1:<port>` with security none, `mode: auto`, a secret path, and xPadding as in §2. Caddy publishes it as `handle /<secret>/*` with `reverse_proxy h2c://…` and `flush_interval -1`, under an own subdomain with its LE cert. Clients use stream-one by default, with packet-up as a twin config.
   - Why: SNI matches the IP, a real site answers probes, it muxes under the 3-connection rule, no new router port, and a CDN can front it later.
   - Risks: a shared free-DNS domain (e.g. `mooo.com`), so a bought domain is safer [LC]. Check that Caddy passes stream-one full-duplex.
   - Clients: Happ, v2rayNG, v2RayTun, Shadowrocket, v2rayN.
2. **The same transport off 443: VLESS + XHTTP (stream-one) + Reality self-steal on 20456/tcp.** SNI = own subdomain; `target` = Caddy (`127.0.0.1:9443` with `xver: 1`, because Caddy expects the PROXY protocol, or a plain loopback listener; to be verified). Fingerprint firefox.
   - Why: n4p#546 shows that "change the port off 443" fixes home-ISP policing.
   - Clients: the same as #1.
3. **CDN-ready XHTTP packet-up (second path on #1, GET uplink, no SSE/gRPC headers).** Build it only once a Yandex or Timeweb CDN account is bought.
   - Clients: Happ or INCY with Xray >26.6.27.
4. **Optional: Hysteria2 + Salamander with port hopping over 20457–20459/udp** (host DNAT into one port, `udpHop` on the client). UDP fallback; hopping counters per-flow throttling. Skip if existing Hy2 inbounds suffice.
   - Clients: Happ, v2rayNG, Hiddify.

**Housekeeping** (not new inbounds):
- Move the remaining apple/icloud/google/ya.ru Reality SNIs to self-steal.
- Take :10358 and the subscription port off the public internet.
- Have clients route `geosite:category-ru` direct, so RU apps never see our IP as the exit.
- Before upgrading to 3x-ui 3.9.0, plan the XDNS client update.

## What we did with it (2026-10-08)

- Built recommendations #1 and #2 as two new inbounds (created via the panel API, dated labels, attached to every subscription with one client each, and added to the member inbound set):
  - **`08.10.26 · 🔒 XHTTP · TLS 443 (Caddy)`**: VLESS + XHTTP (mode auto), security none, listening on 20470/tcp (not router-forwarded). Caddy publishes it on :443 with its own Let's Encrypt TLS for `example.org` at the secret path `XHTTP_PATH` (`.env`): `handle /{$XHTTP_PATH}/*` -> `reverse_proxy h2c://host.docker.internal:20470 { flush_interval -1 }`. `externalProxy` (forceTls tls, example.org:443) makes links advertise 443+TLS. xhttp `extra`: xPaddingBytes 100-1000, scMaxEachPostBytes 500000-1000000, scMinPostsIntervalMs 10-50. Real-client tests through Caddy (loopback): packet-up 261 down / 105 up Mbit/s, **stream-one 348 / 137** (full-duplex works through Caddy), stream-up 331 / 131.
  - **`08.10.26 · 🪞 XHTTP · Reality self-steal`**: VLESS + XHTTP + Reality on 20456/tcp. serverNames `example.org`, target `127.0.0.1:443` (our own Caddy, so probes get our real site), fingerprint `firefox`, xver 0 (works because the target goes through Caddy's public 443 front, which adds the PROXY header itself). Real-client test ~296 Mbit/s.
  - Why: the SNI is our own domain on our own IP and a real site answers probes, which fits the 2026 "grey list" SNI checks; the first needs no new router port, the second is off-443 per n4p#546.
- The earlier "443 dead" Reality configs (borrowed icloud/google SNIs on a home IP) fit the grey-list pattern in §1.
- Not done yet (housekeeping): move the remaining apple/icloud/google/ya.ru Reality SNIs to self-steal; take :10358 and :2096 off the internet; client-side `geosite:category-ru` direct routing; plan the XDNS client update before 3x-ui 3.9.0 (bundles Xray 26.9.30 + TUIC).
- Recommendations #3 (CDN-ready packet-up) and #4 (Hysteria2 port hopping) were not built.
